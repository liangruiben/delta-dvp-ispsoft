# ISPSoft 符号表 CSV 格式（实测校准）

ISPSoft 里可以 `工具 → 导入/导出 → 导入全局符号`（或右键符号表 → 导入全局符号）
批量导入元件名与中文注释。

**符号注释会随程序一起下载进 PLC** —— 以后换台电脑从 PLC 上传程序，中文注释还在。
（WPLSoft 的批注只存在工程文件里、不下装。）

## 1. 文件格式（用真实导出逐字节校准过）

| 项 | 值 |
|---|---|
| 编码 | **GBK / ANSI，不要 BOM** |
| 换行 | CRLF |
| 表头 | `Class,Identifiers,Address,Type,Initial Value,Comment` |

注意第 5 列列名是带空格的 **`Initial Value`**（不是 `Initial`），且**要填初值**。

```
Class,Identifiers,Address,Type,Initial Value,Comment
VAR,前后轴前限位,X0,BOOL,FALSE,零点-前后轴向前回零目标
VAR,脚踏开关,X16,BOOL,FALSE,脚踏启动-上升沿触发走一个循环
VAR,上下轴快速度,D510,WORD,0,Hz 乘D506后得D40
VAR,S20两轴快移,S20,BOOL,FALSE,动作a
VAR,S20起步延时,T213,TIMER,1,固定10ms
```

## 2. Type 与初值

| 元件 | Type | Initial Value |
|---|---|---|
| X / Y / M / S | `BOOL` | `FALSE` |
| **T（定时器）** | **`TIMER`** | **`1`** |
| D 寄存器 | `WORD` | `0` |

> **定时器必须写 `TIMER`，不能写 `BOOL`。** 一律按位元件填 `BOOL` 会让每个定时器行
> 各报一个错 —— 用"N 个错误 = 某类元件行数"就能快速定位。
> （DVP 的专用装置各有自己的类型名；用到计数器 C 时同样要先取一份真实样本确认类型。）

D 寄存器用 `WORD`：DVP 的 D 物理上就是 16 位，用 WORD 不会和相邻寄存器冲突；
即使程序里做 32 位运算（`DMUL`/`DADD`），只要**设定值本身 ≤ 32767**，按 WORD 声明就没问题。

## 3. 标识符命名

* 上限 **16 字符**；可用中文（实测中文标识符合法）
* **禁用符号**：`~ ! @ # $ % ^ & * ( )`
* 不能以数字开头；标识符必须唯一
* 注释里不要出现英文逗号（CSV 分隔符）

## 4. 踩过的坑

* **编码不对**（用了 UTF-8 带 BOM）会导致导入乱码或直接报格式错 —— 用 GBK 无 BOM。
* 文件名 / 列名 / 初值这三处**最容易按文档猜错**：
  正确做法是**让用户在该软件里新建一个符号并导出一次**，拿真实样本逐字节对齐，
  不要照着手册的示例写。
