# 指令表（IL）→ 梯形图网络：切分规则与踩坑

ISPSoft 给 DVP 老机型只开放 **梯形图 LD** 和 **顺序功能图 SFC** 两种语言（`IL` / `ST` / `FBD`
只给 AS/AH/SE 等 IEC 机型）。但**梯形图编辑器自带「指令输入模式」**：选中位置后直接键入
`LD X0` 回车即生成接点，所以录入依然是"敲指令"，只是必须**一个网络一个网络地敲**。

因此把一整份 IL 转成 `.mpu` 时，核心工作就是**把 IL 切成正确的网络**。

## 1. 切分规则

| IL 语句 | 处理 |
|---|---|
| `STL Sxx` / `RET` | **各自独占一个网络**（步进母线段） |
| `LD` / `LDI` / `LDP` / `LDF` / `LD=`… | **起一个新网络** |
| `AND` / `ANI` / `AND=`… | 串到当前网络的条件里 |
| `OR` / `ORI` / `ORP` | 并入当前网络的并联组（最后生成一个 TYPE=6 聚合节点） |
| `OUT` / `SET` / `RST` / 应用指令 | 挂到当前网络的**输出区** |
| `END` | **丢掉**（编译器自动加） |

### 关键：出现"输出之后又有接点"时必须另起网络

IL 里常见这种写法（一个条件驱动多个输出、中间还夹接点）：

```
LD M51
ANI M30
ANI M100
ANI M52
TMR T201 K1
AND T201        ← 输出之后又出现接点
DPLSY D46 D12 Y0
```

梯形图里 `TMR` 是应用指令，**不能再往后串接点**。正确做法是切成两个网络：

```
网络A: 条件 = M51 · ¬M30 · ¬M100 · ¬M52            → TMR T201 K1
网络B: 条件 = M51 · ¬M30 · ¬M100 · ¬M52 · T201     → DPLSY D46 D12 Y0    ← 条件重写一遍
```

`il2mpu.py` 的 `split_nets()` 会自动这么做：**遇到"已经在当前网络里出现过输出"的接点时，
另起网络并把前面的条件复制一份**。

**为什么必须拆**：ISPSoft 梯形图**不支持 MPS / MRD / MPP**（官方明确），并联/分支只能靠
"每个分支各自从母线起"来表达。硬塞进一个网络会被软件合并成一条串联线 —— 条件就错了。

> 真实教训：有人在梯形图上连续输入
> `STL S0 / LDI M30 / TMR T205 K1 / LD T205 / ANI X0 / DPLSY D52 K0 Y0 / RET`，
> 结果被合并成一个网络：`¬M30 → T205 → ¬X0` 三个接点串成一条线，
> `STL / TMR / DPLSY / RET` 四个输出并列挂在后面 —— 逻辑完全变了。
> **"能敲进去" ≠ "结构正确"。**

### 副作用：条件会被复制

拆网络会**复制条件接点**，所以生成文件里的常开/常闭接点数量**会多于** IL 里的
`LD+AND` / `LDI+ANI` 数量，这是**正常的**（`mpu_check.py --ref` 因此对普通接点只做下限校验）。
而 `LDP`、`OUT/SET/RST`、比较接点、各应用指令的数量**可以精确对上**。

## 2. 录入侧注意事项

* **一条支路 = 一个网络**。同一网络里连续输入多条指令会被合并（见上）。
* 应用指令（API）**只能放在网络末尾**，后面不能再接对象。
* 功能块的 En 脚**不能直接接左母线**，必须从某个条件接过来。
* 有多个输出时，ISPSoft 会自动加 `TYPE=29` 聚合节点；有并联输入时加 `TYPE=6` 节点。
  这两类节点**由生成器自动加**，手写文件时不用管。
* 指令大小写不敏感。

## 3. 导入后的任务指派（必做）

报 `周期工作必须指派一个以上的POU` **不是文件问题**，是任务配置问题：

> POU 必须被指派给一个「任务」才会被执行（DVP 只有一个"周期性"任务）。
> 在项目管理区**右键 POU → 工作属性设定 → 工作管理**，把 POU 从「未指派 POUs」
> 移到右侧「已指派 POUs」→ 确定 → 再编译。

在**已有 POU 的项目**里导入不会遇到这个；空项目导入才会。

## 4. 错误码速查

| 错误码 / 提示 | 含义 | 处理 |
|---|---|---|
| 240 `找不到变量K1的定义` | 常量写成了带 `K` 的标识符 | 常量写纯数字：`K1` → `1` |
| 110 `数据类型不正确` | 操作数位宽/类型不符 | 检查该操作数是否写了 `K` 或类型声明冲突 |
| `周期工作必须指派一个以上的POU` | POU 没挂到任务 | 按上面第 3 节指派 |
| `END 是无效指令` | 文件里含 END | 删掉，END 由编译器自动加 |
| 导入直接失败（不报行号） | 容器/加密/结构坏了 | 用 `mpu_check.py` 自检 |

报错格式：`位置[prog0,区段编号：N]` 里的 **N 就是网络号**（`NET_ID`），可直接定位。

## 5. 与 WPLSoft 的关系

WPLSoft 的 `.dvp` 是**另一套闭源编译格式**，与 `.mpu` 不通用，也没有可靠生成办法。
本项目已全部转为 ISPSoft。若手上还有旧 `.dvp`，可用 ISPSoft 的
`文件 → 导入 WPL 项目` 让软件自己转换（一次性工具，之后只在 ISPSoft 里维护）。
